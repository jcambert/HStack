# M9 — Native Execution Providers (2026-10-10)

## Scope and user impact

M9 strengthens HStack's ability to support multiple execution-environment providers **without changing the current default**. The only shipped provider is **native Docker**, orchestrated exactly as before by Compose or Aspire. CLI commands, workspace project YAML, agent auth and project state remain unchanged.

- `IExecutionEnvironmentProvider` interface and plan/handle models define an isolation-provider boundary separate from `IWorkspaceOrchestrator`.
- `NativeContainerExecutionProvider` protects preview/start/restart through fail-closed admission; stop/down is still permitted for recovery from invalid legacy configs.
- Capability tests reject privileged/host namespaces, container root write access, missing no-new-privileges or cap-drop, host-root mounts, Docker socket/pipe mounts, non-loopback ports, unisolated state or unsupported orchestrators.
- Dagger Container Use and DevPod were **evaluated in desk research only**. Neither was installed or tested in CI and neither is a selectable provider. Security parity is not established; immediate adoption is **No-Go**.

## Guarantees and limitations

No Docker/Compose/Aspire, agent or OpenViking image dependency was changed. No new Docker socket mounts or privileged policy was allowed. Linux x64 real runtime was checked; Windows runtime and native ARM64 OCI are **not** claimed to have been covered. Existing root-owned OpenViking directories can still need backed-up ownership migration. External upstream sandbox security has **not been runtime proven** and requires separate authorization/proof before any future integration.
