# PBI-1602 — Transactional managed update apply

**Epic:** EPIC-016  
**Priority:** Critical  
**Status:** Done

## Description
Apply an approved managed toolchain update without mutating running workspaces until the candidate image is built and validated.

## Acceptance Criteria
- `hstack update plan` exposes the ordered transaction.
- `hstack update apply --yes` creates a config backup before mutation.
- The downloaded lock is validated with the existing pin/checksum rules.
- A candidate full workspace image is built without replacing the active full-image tag.
- Only workspaces that were running are stopped/recreated.
- Candidate workspaces must become healthy and all registered agents must be detected.
- The active toolchain lock and final image tag are committed only after validation.
- On failure, the prior active lock is restored and previously running workspaces are recreated with their old plan.
- CLI self-update is explicitly outside the in-process image transaction and requires installing the matching release package.

## Security Requirements
HTTPS-only metadata, no `latest`, corporate CA/proxy policy retained, no TLS bypass.

## Test Strategy
Unit-test plan ordering; rely on existing Docker regression gates for workspace orchestration and keep apply confirmation explicit.

## User Stories
US-1602.

## Definition of Done
Plan, candidate-image transaction, rollback, active-lock persistence, help/docs and CI are complete.
