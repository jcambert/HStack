# PBI-1503 — Project-scoped memory

**Epic:** EPIC-015  
**Priority:** Critical  
**Status:** Done

## Description
Give each HermesStack project a distinct OpenViking user/API key and project-specific client state.

## Business Value
Durable memory remains useful without allowing ProjectA private context to leak into ProjectB.

## Dependencies
PBI-1501, PBI-1502, secrets subsystem.

## Acceptance Criteria
- Every project maps to a dedicated provider identity.
- Private `viking://~/` resolution happens under that authenticated identity.
- Project API keys stay in protected secret storage/client state.
- Root/admin keys never enter workspace environment variables.

## Security Requirements
Fail closed on invalid project ids and global scope; no cross-project shared credential.

## Observability Requirements
`memory inspect` reports provider/account/user without exposing keys.

## Test Strategy
Scope mapping, workspace plan and M6 security gate.

## User Stories
US-1505.

## Existing Solutions Review
Use OpenViking multi-user identity isolation instead of inventing virtual namespaces.

## Definition of Done
Identity provisioning, workspace wiring, isolation checks and docs are complete.
