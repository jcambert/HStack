# PBI-1501 — Context provider abstraction

**Epic:** EPIC-015  
**Priority:** High  
**Status:** Done

## Description
Introduce provider-neutral context contracts and registry so HermesStack owns policy/lifecycle while specialized context providers own storage and retrieval.

## Business Value
Prevents OpenViking-specific logic from leaking into core application services and keeps future providers replaceable.

## Dependencies
M1 control plane; Integration-first architecture.

## Acceptance Criteria
- `IContextProvider` and provider registry exist.
- Project provisioning, sessions, retrieval, writes, sharing and export/import are provider-neutral.
- Unknown or duplicate providers fail explicitly.

## Non-functional Requirements
Async/cancellation-aware; no provider switch statements in core flows.

## Security Requirements
Provider selection cannot bypass scope, budget or secret policies.

## Observability Requirements
Provider id is recorded in retrieval traces and doctor output.

## Test Strategy
Unit-test registry and service policy paths; CI build on Linux and Windows.

## User Stories
US-1501, US-1507.

## Existing Solutions Review
OpenViking remains the initial specialist provider; HermesStack only defines the integration boundary.

## Definition of Done
Contracts, registry, tests, docs and CLI composition are complete and green.
