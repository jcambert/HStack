# PBI-2302 — Native Container Execution Provider

**Milestone:** M9. **Status:** Implemented and tested by PR #19 candidate CI #146; main validation pending. **Depends on:** PBI-2301.

## Existing Solutions Review
Existing Compose, Aspire and Docker workspace code already implement secure container settings. Wrap/reuse this behavior with an explicit native provider rather than introducing a parallel Docker engine.

## Work
Deliver `NativeContainerExecutionProvider` or named equivalent, sharing current Docker image, state directories, mounts and policy enforcement. Define provider detection, lifecycle ownership and failure rollback. Keep user-visible project IDs and commands stable, with Compose/Aspire as orchestrators.

## Acceptance criteria
- Given an existing project, when up/down/restart/shell/status are run on both Compose and Aspire, then behavior and persisted state match pre-M9 baselines.
- Given a health or runtime failure, then cleanup/rollback follows existing ownership without orphaned untracked containers.
- Given a provider selection, then native Docker is default and no implicit migration occurs.
- Linux Docker runtime smoke plus Windows build/unit validation pass using real pinned toolchain.

**Out of scope:** external sandbox integrations before native stabilization.
