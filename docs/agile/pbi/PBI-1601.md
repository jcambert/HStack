# PBI-1601 — Managed update metadata and version check

**Epic:** EPIC-016  
**Priority:** Critical  
**Status:** Review

## Description
Add a non-destructive update check that compares the embedded pinned toolchain with the HermesStack-managed update channel.

## Business Value
Operators can see drift and approved upgrades before rebuilding or recreating any workspace.

## Dependencies
Pinned `toolchain.lock.yaml`; M4 network/certificate support; existing Linux/Windows CI.

## Acceptance Criteria
- `hstack update check` reports HermesStack, workspace image and every pinned managed integration.
- Update metadata is retrieved over HTTPS only.
- The managed channel is the repository `main` toolchain lock, not arbitrary upstream `latest` values.
- The command performs no update, package installation, workspace stop or image mutation.
- Semantic versions distinguish current, available and locally-ahead states.
- Missing or non-semantic metadata is reported without guessing.

## Non-functional Requirements
Cancellation-aware network I/O; bounded manifest size; no new external package dependency.

## Security Requirements
No TLS bypass; no use of unpinned upstream `latest`; update metadata remains subject to the existing pinned lock validation.

## Observability Requirements
CLI output shows the exact managed metadata source.

## Test Strategy
Unit-test update comparison states and run an end-to-end CLI smoke check against the managed channel.

## User Stories
US-1601.

Domain/application/infrastructure/CLI slice, tests, CI gate and Agile documentation are complete.
