# ADR-022 — Lossy optimizer stacking requires explicit consent

**Status:** Accepted  
**Date:** 2026-10-05

## Decision

Optimizer pairs are classified Compatible, Redundant, PotentiallyLossy or Unsupported.

RTK + Caveman is PotentiallyLossy because one compacts tool output while the other may alter response semantics. HermesStack never activates this stack automatically. Caveman requires aggressive/custom profile plus explicit `--allow-lossy-stack` when another optimizer is active.
