# ADR-024 — Blazor WebAssembly as an untrusted local control client

**Status:** Accepted for M10 candidate; runtime acceptance pending CI.

## Context / existing solution

The CLI already owns project, secret, Docker Compose/Aspire, OpenViking and Herdr orchestration. A second Docker backend or arbitrary browser terminal would duplicate security-sensitive behavior. The local web interface must reuse these services without changing defaults or project config.

## Decision

- `HermesStack.Web.Client` is a **.NET 10 Blazor WebAssembly** application using **MudBlazor 9.11.0**, serving only display DTOs and an ephemeral CSRF token.
- `HermesStack.Web.Host` is a standalone **ASP.NET Core 10** executable that hosts the static WASM assets and delegates to existing Application service classes, Compose/Aspire and the M9 native execution provider. The CLI `hstack ui` runs this adjacent packaged executable; no hidden process is created by normal CLI calls.
- `HermesStack.Web.Contracts` types contain only explicitly permitted project status, version and UI data. Project source and agent credentials are never embedded into the WASM assembly.
- The host binds only to the numeric IPv4 loopback `127.0.0.1` over HTTPS with a short-lived self-signed certificate; the user sees a trust warning instead of a TLS bypass.
- Each server start issues a **one-use** bootstrap token in a URL fragment, which cannot be logged by the HTTP server. The opening document exchanges it for an **HttpOnly, Secure, SameSite=Strict** session cookie. API writes require an `Origin` match and `X-HStack-CSRF` token; all requests validate `Host`, local socket binding and origin. Unauthenticated requests cannot retrieve WASM assets or API data.
- API provides allowlisted project registration/edit/delete, lifecycle and ports, backup, bounded redacted workspace logs, statuses, pinned-toolchain diagnostics and bundled Markdown guides. Every destructive action uses explicit confirmation. No `/exec`, arbitrary shell or generic Docker control route.
- The UI never handles interactive provider authentication, persistent agent tokens, local secret-store data or direct Docker sockets.
- **MudExtensions / CodeBeam.MudBlazor.Extensions is not installed**: no component is currently required that justifies extra attack surface and dependency weight; revisit after a concrete need and pin compatibility.
- Each release bundle includes both CLI and Web.Host as adjacent executables, linked only through existing project state. UI absence does not affect CLI operation.

## Residual risks and follow-up

- Self-signed HTTPS shows a browser warning until a secure local trust-onboarding solution is chosen.
- One-use token establishes a single locally authenticated browser session; do not use for LAN/remote/multi-user scenarios.
- Browser cannot authenticate agents directly; commands are displayed to the user for secure terminal use.
- Tests must cover unauthorized access, malicious Origin/Host, CSRF, replay, project parity and static assets; real browser automation and Windows device testing should be explicitly evidenced before claiming universal platform readiness.
- Status polling can generate Docker process queries; avoid aggressive refresh.
