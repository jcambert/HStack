# ADR-016 — Herdr owns M3 sessions; tmux remains a fallback

**Status:** Accepted  
**Date:** 2026-10-05

## Context

The V5 plan names both Herdr and tmux for M3. Current Herdr releases now provide their own persistent background server, workspace/tab/pane model, JSON automation API and native agent-session restore integrations.

## Decision

HermesStack integrates Herdr directly as the logical session owner. tmux remains installed and is exposed through `hstack tmux` for recovery and simple manual multiplexing, but Herdr is not nested inside tmux.

## Consequences

This preserves the V5 requirement to ship both tools while avoiding two competing layers of pane/session ownership. Session persistence stays project-scoped and direct M2 agent launch remains available.
