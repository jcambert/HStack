# ADR-006 — OpenViking as initial context provider

**Status:** Accepted  
**Date:** 2026-10-06

## Context

HermesStack needs durable project context but remains an integration-first control plane. Reimplementing retrieval, vector storage or memory extraction would enlarge the security and maintenance surface.

## Decision

Use OpenViking as the first `IContextProvider`. HermesStack owns deployment, project-to-user mapping, shared ACL policy, context budgets, secret filtering and lifecycle. OpenViking retains ownership of resources, memories, skills, sessions, retrieval and the `viking://` model.

Each project receives a distinct OpenViking user/API key. Provider-wide global context is denied in M6; cross-project access uses explicit restricted ACL namespaces.

## Alternatives

A custom memory engine and a single shared OpenViking user were rejected.

## Consequences

OpenViking is pinned and compatibility-tested. Root/admin credentials stay host-side. Future providers can implement the abstraction without changing core policy.
