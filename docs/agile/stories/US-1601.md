# US-1601 — Check managed updates

As an operator I want to run `hstack update check` so that I can see approved HermesStack/toolchain changes before modifying any workspace.

## Context
M7 starts with a read-only update inventory. The approved channel is HermesStack's pinned `toolchain.lock.yaml` on `main`, preserving checksum and reproducibility policy.

## Acceptance Criteria
Given a valid local pinned toolchain, when `hstack update check` runs, then every managed component is compared with the HTTPS update manifest and the command does not mutate local state.

## Edge Cases
A missing component is reported as unavailable; a locally newer semantic version is reported as ahead; non-semantic differences are reported as changed.

## Security Considerations
HTTPS is mandatory. The command must not trust arbitrary provider `latest` values or disable certificate validation.

## Test Cases
Current/update/ahead/unavailable comparison unit tests plus CLI smoke execution against the managed manifest.
