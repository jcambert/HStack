# US-1505 — Prevent ProjectA memory leaking into ProjectB

As a developer I want private project memory isolated so that one project cannot retrieve another project's durable context.

## Acceptance Criteria
Given ProjectA and ProjectB have memory enabled, when each is provisioned, then each receives a different provider user/API key and private queries use authenticated `viking://~/` space; global scope fails closed.

## Edge Cases
Invalid project ids and accidental global queries are rejected.

## Security Considerations
This story is a release blocker.

## Test Cases
Scope mapper, workspace-plan and provider security gates.
